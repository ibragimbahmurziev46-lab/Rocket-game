# Public Schedule

Табло расписания занятий колледжа в стиле авиационного табло. Фронтенд — React + TypeScript (Vite), бэкенд — FastAPI.

## Структура проекта

├── backend/
│   ├── main.py
│   └── venv/                (создаётся при установке, в git не коммитится)
├── frontend/

│   │   ├── App.css

│   ├── package.json

## Установка и запуск

Проект требует **два параллельно работающих терминала** — один для бэкенда, один для фронтенда.

### Терминал №1 — Бэкенд

cd backend
python -m venv venv

Активация виртуального окружения:

Windows (cmd / PowerShell):
venv\Scripts\activate

Linux / macOS:
source venv/bin/activate

Установка зависимостей и запуск:

pip install fastapi uvicorn
uvicorn main:app --reload --port 8000

Проверка: откройте в браузере http://localhost:8000/api/schedule. Должен вернуться JSON со списком пар. Терминал не закрывать.

### Терминал №2 — Фронтенд

Из корня public_schedule:

cd frontend
npm install
npm run dev

Vite выведет адрес (обычно http://localhost:5173). Откройте его в браузере.

## Использование

- Экран показывает текущее время и список предстоящих пар.
- Пары, начавшиеся более 10 минут назад, автоматически скрываются (строка «переворачивается», на её месте появляется следующая).
- Каждые 10 секунд выполняется холостой переворот всех строк — визуальная имитация обновления табло.
- Строка идущей пары помечается статусом ИДЕТ в четвёртом столбце.

### Тестовое время

Для отладки фильтрации можно подменить текущее время через query-параметр:

http://localhost:5173/?mockTime=09:00
http://localhost:5173/?mockTime=10:25

Часы будут тикать от указанной точки. Чтобы вернуться к реальному времени — уберите параметр из адресной строки и перезагрузите страницу (F5).

Важно: mock-время подставляется в **сегодняшнюю** дату. Тестовые пары бэкенда тоже генерируются на текущий день, поэтому проверка работает в любой день.

## Возможные проблемы

### 1. PowerShell блокирует npm: «выполнение сценариев отключено в этой системе»

Симптом:
npm : Невозможно загрузить файл C:\Program Files\nodejs\npm.ps1, так как выполнение сценариев отключено

Решение (PowerShell, один раз):
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

Подтвердите Y. После этого закройте и заново откройте PowerShell.

Альтернатива: работайте в cmd вместо PowerShell и вызывайте npm как npm.cmd install, npm.cmd run dev.

### 2. npm install падает с ошибкой ENOENT: no such file or directory, open '...package.json'

Причина: команда npm create vite@latest frontend -- --template react-ts не выполнилась (обычно из-за проблемы №1), папка frontend пуста.

Решение:
Remove-Item -Recurse -Force frontend
npm create vite@latest frontend -- --template react-ts
cd frontend
npm install

На вопрос о линтере выбрать ESLint.

### 3. Красные подчёркивания в App.tsx (не найдены модули react)

Причина: не установлены зависимости или TypeScript-сервер не видит node_modules.

Решение:
1. Убедитесь, что npm install завершился без ошибок.
2. В VS Code: Ctrl+Shift+P → TypeScript: Restart TS Server.

### 4. Браузер открывает стандартную страницу Vite («Get started / Count is 4»)

Причина: пользовательский код не заменён в src/App.tsx / src/App.css / src/index.css.

Решение: полностью очистите index.css и вставьте код из документации проекта в App.tsx и App.css. Сохраните все три файла (Ctrl+S) — Vite перезагрузит страницу автоматически (HMR).

### 5. Таблица пустая, в консоли браузера ошибки сети

Причина: бэкенд не запущен или запущен на другом порту.

Решение:
- Проверьте, что терминал №1 с uvicorn активен и не показывает ошибок.
- Откройте http://localhost:8000/api/schedule напрямую в браузере.
- Если порт 8000 занят, запустите бэкенд на другом порту (uvicorn main:app --reload --port 8001) и измените API_URL в frontend/src/App.tsx.

### 6. Порт 5173 уже занят

Vite автоматически выберет следующий свободный порт (5174, 5175 и т.д.) и напишет его в терминале. Используйте указанный там адрес.

### 7. Кириллица отображается квадратами или неправильно

Причина: шрифт JetBrains Mono подгружается с Google Fonts, нужен доступ к интернету.

Решение: проверьте сетевое соединение. Для работы в закрытой сети потребуется скачать .woff2-файлы шрифта и подключить их локально через @font-face в App.css, положив файлы в public/fonts/.

### 8. Все пары скрыты, хотя расписание есть

Причина: фильтр «прошло более 10 минут». Если тестируете вечером, все утренние пары уже истекли.

Решение: используйте ?mockTime=08:55 (или любое время за 10 минут до интересующей пары) для отладки.

## Остановка

Ctrl+C в каждом из двух терминалов.

## Известные ограничения

- Источник данных — заглушка в backend/main.py. Для интеграции с реальным расписанием нужно заменить тело функции get_schedule.
- Длительность пары зашита как 80 минут в App.tsx (константа в FlipRow). При появлении пар с разной длительностью (85 мин, 5-минутные перемены) потребуется вынести end_time в ответ API.
- CORS в main.py открыт для всех источников (allow_origins=["*"]). Для продакшена — ограничить конкретным доменом.
